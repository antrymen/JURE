# Broad Screening v0.1 — Clue Discovery Stage III

**Architecture:** This package is the statistical backend for Clue Discovery Stage III, Broad Response Landscape Organization. The generic entrypoint is `python -m clue_discovery.run`; contracts and adapters live in `clue_discovery/`. Triage and Deep Agents are downstream, optional consumers. See the [method definition](../docs/clue_discovery/JURE_Clue_Discovery_Method.md). The reproduction CLI below retains its application-specific historical defaults.

Offline, post-hoc characterization of the frozen Day 6 perturbation-response landscape. No candidate requalification, scan execution, new significance tests, biological naming, external services, Day 8 access or Deep Agent calls.

## Reproduce

```bash
.venv/bin/python -m broad_screening.run --output outputs/broad_screening_v01_reproduction
```

An existing output directory is never overwritten. Defaults audit and reuse `outputs/broad_screening_v01_landscape_20260927/` and `outputs/perturbation_scan_day6_v01_20260927/`. The initial grouping and matrix are identity-checked against frozen artifacts. All PCA dimensions are newly exported; bootstrap partitions are reconstructed to add paired ablation and per-replicate group alignment. Compatible cached co-assignment is verified and reused.

`--bootstrap-repetitions 100` requests a new 100-repeat run. `--config path.yaml` accepts fields from `config.Config`, including configurable cuts, core thresholds, structural strata and explicit `bootstrap_enabled` / `stable_core_enabled` ablation switches. Disabling bootstrap marks stability unassessed. All settings are frozen before computation in `audit/config_frozen.yaml`.

## Definitions

- Effect matrices and module median activities use **percentage points**. Candidate objects also retain the original `delta` frequency fraction and exact source interval fields.
- `+`/`−` in a state means detected/undetected. Effect enrichment/depletion describes the frequency of that complete state, not differential gene expression.
- Main matrices include candidate-bearing targets; all-target matrices distinguish insufficient support (NA), tested nonqualification, below-effect gate and selection. Nonselected observed effects are not biological zero.
- Pattern groups use signed continuous profiles, Pearson distance, average linkage and a default cut of 0.30. Target groups reuse audited continuous-profile cosine clustering.
- Cores use the largest deterministic complete-linkage block with every pair's co-assignment ≥0.80 and at least two members. Ties use mean pair stability and reference IDs. This is not a maximum-clique algorithm or external replication.
- Representatives are response-correlation medoids. Whole and core annotation objects each have an in-object medoid; empty cores have none.
- Module activity defaults to median signed delta. Historical standardized-mean activity is exported separately; the correlations need not be identical.
- Gene-only ablation is **OR of candidate masks within a triplet**. The state-preserving binary bridge isolates state collapse from continuous-to-binary encoding changes. Common-evaluable-domain metrics and cross-triplet stability prevent unequal coverage or trivially duplicated states from being mistaken for an advantage.
- Sensitivity matching uses membership Jaccard then response-centroid correlation, with explicit split/merge context. Module IDs never determine matches.
- Structural labels are configurable organizational rules. They are not biological importance, novelty, p-value or final selection scores. Empty strata are reported as zero.
- `target_burden.csv` covers the primary cohort; `all_targets_burden.csv` preserves the full scan denominator. Sample-size correlations are stratified by cohort and effect-summary population.

## Case-set audit

```python
from broad_screening import evaluate_case_set_coverage
from broad_screening.coverage import candidate_coverage_by_module, candidate_coverage_by_pattern

coverage = evaluate_case_set_coverage(case_ids)  # Explicit, known IDs only; no auto-selection.
top4 = candidate_coverage_by_module(4)
top20_states = candidate_coverage_by_pattern(20)
```

`evaluate_case_set_coverage` rejects unknown or duplicate IDs and handles an empty set. It reports modules, effect directions, stable cores, target clusters, targets, organizational blocks and overlapping strata. `deep_case_pool.jsonl` retains all candidates and original support/statistical provenance. It is not a ready-to-execute Case File adapter.

## Outputs and verification

`LANDSCAPE_REPORT.md`, `RESULTS_SUMMARY.md`, `METHODS_DRAFT.md`, `RESULTS_DRAFT.md`, complete matrices/tables, paired bootstrap and sensitivity traces, whole/core annotation objects, unselected case pool, figure-ready data and source/output SHA-256 manifests. Graphic rendering is deferred at the user's request; no PNG/SVG/PDF is generated by this pipeline.

```bash
.venv/bin/python -m pytest -q tests/test_broad_screening.py tests/test_landscape_analysis.py
```

The production run independently checks source identities, unchanged effects/masks/statistical fields, core pair thresholds, case coverage, exact OR collapse, unsupported NA handling, figure-data hashes and evidence scope. Q1–Q5 are explicitly answered in `audit/acceptance_questions.json`; a sensitive or mixed result is reported instead of tuned to a historical result.
